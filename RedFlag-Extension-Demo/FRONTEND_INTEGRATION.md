# RedFlag frontend — displaying backend/ODU LLM results

This folder contains **frontend files only**. No Flask/backend code was modified.

## What changed

- `content.js`: continues to send `{ "text": "..." }` to `POST http://127.0.0.1:5000/analyze`, now reads dynamically returned LLM labels/explanations and matches `claim`/`matched_text` instead of requiring a regex `pattern`. It also displays an example query sent and response received in the floating RedFlag panel. Existing `pattern` responses still work.
- `content.css`: styles the query/response preview and ensures it can be scrolled into view.
- `popup.js`: removes references to fixed demo-rule results and shows the backend error message when relevant.
- `demo.html`: removes the hardcoded expected finding count.

## Run the updated frontend

1. Keep the existing Flask backend running (`python app.py`) in its own folder. It is **unchanged** and, for now, still uses regex rules.
2. Unzip this package. In Chrome, open `chrome://extensions`, enable **Developer mode**, and use **Load unpacked** to choose the `redflag-frontend` folder. Or replace these frontend files in your existing extension folder and click **Reload**.
3. Open the included `demo.html` (enable **Allow access to file URLs** for the extension), or visit a supported normal webpage. Click the floating **RedFlag** button.
4. The **Example analysis request and response** area displays text sent to `/analyze` and the server's actual reply. Findings above/below it use response-provided labels and explanations.

## Required response shape for the backend team

The frontend does not know the private ODU LLM endpoint, credentials, or the backend team's routing, and **does not contact ODU directly**. The backend must accept the same existing request:

```json
{"text":"The claim on the webpage to analyze."}
```

Recommended LLM-backed response:

```json
{
  "flagged": true,
  "claim": "The exact phrase found on the webpage",
  "label": "Potential misinformation",
  "reason": "The explanation generated by ODU's LLM",
  "flagtype": "redflag"
}
```

When not flagged:

```json
{"flagged": false}
```

To return more than one finding:

```json
{
  "findings": [
    {"claim":"exact phrase", "label":"Potential misinformation", "reason":"Explanation", "flagtype":"redflag"},
    {"claim":"second phrase", "label":"Unverified wording", "reason":"Explanation", "flagtype":"signal"}
  ]
}
```

Supported types: `redflag`, `biasstar`, `signal`. If `claim` is absent or cannot be found verbatim, RedFlag highlights the entire analyzed passage. It also accepts legacy `pattern` regex fields and JSON returned as a string inside `response`, `result`, or an OpenAI-style `choices[0].message.content` field.

**Plain-text responses** display in the request/response area but do **not** create a misinformation flag by themselves: the backend must include structured findings (such as `flagged: true`) for highlighting.

To avoid overwhelming an LLM integration, the frontend currently analyzes at most 50 eligible text nodes per scan and caches previous responses for unchanged text. This limit is adjustable near the beginning of `content.js`.

**Security:** Do not put ODU API keys or other secrets in any Chrome extension file. Keys belong on the backend only.
